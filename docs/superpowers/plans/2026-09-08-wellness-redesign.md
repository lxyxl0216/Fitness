# Fitness 完整记录与界面改版

用户要求：应用 design-taste-frontend 设计更好的界面，并补齐截图缺少的核心功能。

## 设计审查与决策

原版橙色 + 系统卡片，四个 Tab 为今日、计划、历史、身体。训练与身体记录可用，但首页重复模板卡片占比过大，计划文字随按钮染色导致弱对比，缺少饮食与完整训练周期。

原生移动端不属于指定技能的直接适用范围，因此应用其审查、配色、密度、层级原则，使用 Apple HIG / SwiftUI 实现。保留 Fitness 品牌、现有记录、训练完成流程与本地存储。

视觉参数：DESIGN_VARIANCE 6 / MOTION_INTENSITY 3 / VISUAL_DENSITY 5。冷灰底，深松绿强调，系统无衬线字体和等宽数字。卡片 22pt，表单 12pt，主要按钮 capsule。按钮用固定深绿色 + 浅字，正文独立于 tint。亮暗随系统，44pt 触控，支持大字。

## 功能与文件

1. `Core/WellnessModels.swift`：食物每份营养、餐次日志、餐单、个人档案、手填营养目标、训练周期和逐动作处方。原有 Codable 字段继续解码，新数据使用可选字段兼容旧文件。
2. `Core/WellnessStore.swift`：校验、食物/补剂 CRUD、餐单与日志快照、摄入汇总、周期日期映射、采购合并。`FitnessStore` 沿用原子写入并允许扩展同一个存储。
3. `Views/DesignSystem.swift` 与四个 Tab：今日营养主摘要与训练入口；训练含计划、动作、历史；趋势含营养与体重；我的集中档案、目标、食品、餐单、采购、补剂和备份。
4. 编辑器全部可保存与取消，空状态提供下一步；未填写目标与数据保持未设置，不伪造数字。食品数值由用户根据标签录入，记录使用快照避免修改食品影响历史。
5. 训练支持逐组次数、目标 RPE、休息秒数，周期中可包含休息日；计时结束时间保存，退出后按实际时钟恢复。
6. 动作库提供肌群和器械筛选、动作详情文字和用户设置的 HTTPS 演示链接。未经核实授权的第三方 GIF 不打包，不用生成动画冒充动作示范。

## 验证

- 测试先行：迁移旧文件、餐次和日期边界、份量换算、错误输入、历史快照、删除、周期休息日、处方与上一组、计时恢复。
- macOS `swift test` 与 iOS 编译。
- iPhone UI 用例：录入食物和目标、记录餐次、创建餐单、训练归档、重启恢复。模拟器截图检查亮暗、空状态、主要屏幕。保留小体积独立截图 artifact。
