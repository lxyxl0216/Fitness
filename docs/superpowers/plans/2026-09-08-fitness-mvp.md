# Fitness 第一版实现计划

目标：离线完成模板 → 训练 → 历史 → 身体记录闭环，iOS 17 起支持。

根据本次用户要求直接执行前文已讨论的个人健身 App 第一版。采用 SwiftUI、Observation、Charts；少量结构化记录使用 Codable JSON 原子写入，无第三方运行时依赖。

## 范围与验收

- 今日：本周训练次数、已完成组数、最近体重、开始/继续训练。
- 计划：预置推/拉/腿模板，自建、编辑、删除模板，从本地动作目录选择动作。
- 训练：每组重量（kg）、次数、完成标记、增删组、上次表现。每次编辑保存草稿；只能完成至少一组有效训练；只归档已完成组。
- 历史：倒序记录、训练详情、容量（完成组重量 × 次数）、确认后删除。
- 身体：体重、可选体脂和腰围，日期、趋势与记录删除。照片、3D、GIF、自动加重建议后续实现。
- 保存失败时保留原状态、显示可重试错误；读取损坏数据时阻止覆写。空数据不制造训练统计。

## 执行顺序

1. `Tests/FitnessCoreTests` 定义异常数值、未完成组统计、草稿重启、归档、历史参考、模板独立性与保存失败用例；`Package.swift` 让真实核心代码在 macOS 上用 `swift test` 验证。先推送测试验证缺失实现，再编写核心。
2. `Fitness/Core/Models.swift` 定义 Codable 值模型与纯计算，`Fitness/Core/FitnessStore.swift` 负责原子存储与业务变更，`Fitness/Core/ExerciseCatalog.swift` 提供内置动作。
3. `Fitness/Views` 按四个 Tab、训练编辑器、模板编辑器、身体表单拆分页面。共享服务在 App 根注入，编辑草稿每次变更落盘。
4. Actions 运行核心测试、iOS 编译和模拟器 UI 冒烟测试。UI 用例覆盖开始、完成一组、归档、重启后历史、体重录入，并留截图。
5. 更新 README，检查差异，提交推送，等待云端结果；以实际通过结果报告，不将编译等同于已安装到真机。
